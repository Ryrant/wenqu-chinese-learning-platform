# 试点学校可用版本设计

## 背景

远程 `main` 已完成标准 Cloudflare Workers 自托管部署适配，项目具备 ChatGPT Platform Sites、本地开发和标准 Workers 三种运行路径。当前平台已有学生、教师、家长和机构管理员四端工作台，以及 D1/R2 持久化、来源化模板生成、内容上传、作业提交、批阅、邀请和审计等基础能力。

下一阶段目标是从 demo 走向真实学校试点。试点版本优先保证端到端闭环可靠：机构能部署系统、创建成员、上传教材、发布任务、学生提交、教师批阅、家长查看报告。AI 能力作为辅助能力嵌入闭环，不作为系统正确性的前提。

## 目标

- 支持管理员创建教师、学生、家长和管理员账号，并设置临时密码。
- 支持成员使用邮箱和密码登录，首次登录必须修改临时密码。
- 支持学生与监护人多对多绑定。
- 支持 PDF、DOCX、TXT 自动抽取文本、切片、人工审核发布和关键词检索。
- 支持学生问答和教师备课调用真实文本模型，并保留来源引用和模板降级。
- 支持文字作业 AI 辅助批阅建议，教师确认后才写入正式评分和掌握度。
- 保持现有 Cloudflare Workers、D1、R2、Next/Vinext 架构和 ChatGPT Sites 兼容性。

## 非目标

- 不新增 Cloudflare Vectorize。
- 不做 OCR。
- 不做音视频转写。
- 不做自动语音评分。
- 不做复杂 RBAC、年级主任、校区层级或组织树。
- 不接入第三方 SSO。
- 不让 AI 自动批阅结果直接入库。
- 不进行大规模 UI 重设计。

## 架构与模块边界

继续采用现有 Next/Vinext + Cloudflare Workers + D1/R2 单体架构。第一阶段不更换技术栈，不新增队列、Vectorize 或第三方身份系统。

新增能力按模块拆分，避免继续扩大 `platform-store.ts` 和 `workspace/actions` 的职责：

- `auth`：邮箱密码登录、密码哈希、临时密码、首次改密和会话 token。
- `membership`：成员创建、角色授权、账号状态、学生与监护人绑定。
- `content`：PDF/DOCX/TXT 上传、文本抽取、切片、状态流转和审核发布。
- `retrieval`：租户内已发布知识片段关键词检索。
- `ai`：provider 抽象、OpenAI provider、来源化模板 fallback 和来源约束。
- `assessment`：文字作业 AI 批阅建议、教师确认和掌握度更新。
- `workspace`：保留为前端聚合读取入口，不承载全部业务写操作细节。

所有跨角色访问必须经过租户、角色和成员关系校验。AI 密钥只存在服务端环境变量或 Cloudflare Secret 中，不暴露给前端。

## 账号、成员与权限

当前标准登录只有初始管理员账号。试点版本将其扩展为基础多用户账号系统。

### 成员创建与登录

管理员创建成员时填写：

- 邮箱
- 显示名
- 角色
- 临时密码
- 可选班级归属
- 可选学生与监护人绑定关系

系统只保存密码哈希，不保存明文临时密码。成员第一次使用临时密码登录后进入强制改密流程；未完成改密前不能进入业务工作台。

管理员可以：

- 创建成员
- 重置成员临时密码
- 停用或启用成员
- 调整成员角色
- 维护学生与监护人绑定关系

所有成员创建、重置密码、停用账号、角色变更和绑定关系变更都写入审计日志。

### 数据模型调整

在保持现有表结构方向的基础上新增或调整字段：

- `users.password_hash`
- `users.must_change_password`
- `users.status`
- `users.last_login_at`
- `role_memberships.status`
- `guardian_student_links.status`

保留 `role_memberships` 多角色模型。试点阶段只支持 `student`、`teacher`、`guardian`、`admin` 四类角色。

### 权限策略

- 管理员可管理当前租户内成员、班级、内容、任务和审计。
- 教师只能管理自己任教班级、任务和相关提交。
- 学生只能查看自己的任务、提交和已确认成长档案。
- 家长只能查看已绑定学生的数据。
- 涉及学生数据的读写必须额外校验教师-班级、学生本人或监护人绑定关系。
- API 错误不泄露账号是否存在、密码细节或未授权对象信息。

## 内容管线与检索

试点版本支持 PDF、DOCX、TXT 自动抽取文本、切片、人工审核发布和关键词检索。不支持 OCR、音视频转写、Vectorize 或版本对比。

### 上传与处理流程

1. 管理员上传文件到 R2。
2. 服务端在 D1 写入 `source_documents`。
3. 服务端根据文件类型抽取文本：
   - TXT：按 UTF-8 文本读取。
   - DOCX：解析正文文本。
   - PDF：提取可复制文本。
4. 文本按段落和长度切片，写入 `knowledge_chunks`。
5. 切片默认未发布。
6. 管理员在内容中心预览片段并审核。
7. 审核通过后，文档和片段进入发布状态，可被问答、备课和批阅建议检索。

扫描版 PDF 不做 OCR。无法抽取文本时，文档进入失败状态，并记录可面向管理员展示的错误摘要。

### 状态机

- `uploaded`：文件已保存，等待处理。
- `processed`：文本已抽取并切片，等待审核。
- `published`：人工审核通过，可用于检索。
- `failed`：抽取失败，保留错误摘要。
- `rejected`：人工拒绝发布。

### 检索策略

第一阶段继续使用 D1 关键词检索，但需要比 demo 更明确：

- 查询词标准化。
- 简单关键词拆分和匹配。
- 只检索当前租户内 `published=1` 且文档 `processing_status='published'` 的片段。
- 返回文档标题、片段 excerpt、匹配原因、引用 ID。
- 没有检索结果时，AI 生成拒绝知识型回答。

## AI provider 与来源化生成

第一阶段接入真实文本模型，但所有知识型输出必须受来源约束。

统一生成链路：

1. 检索当前租户已发布知识片段。
2. 无来源时拒绝知识型生成。
3. 有来源时构造带引用上下文的 prompt。
4. 调用 AI provider。
5. 解析模型输出。
6. 保存 `ai_sessions` 和 `citations`。
7. 前端展示草稿、provider 状态和引用来源。

### 模块设计

- `ai/provider.ts`
  - 定义 `generateText({ purpose, prompt, contextChunks, role, level })` 接口。
  - 返回文本、provider、model、token 统计和引用映射。
- `ai/openai-provider.ts`
  - 使用 `OPENAI_API_KEY` 或兼容现有 `AI_API_KEY`。
  - 模型名通过 `AI_MODEL` 配置。
- `ai/template-provider.ts`
  - 保留当前来源化模板 fallback。
  - 未配置模型、模型调用失败或模型不可用时启用。
- `ai/grounding.ts`
  - 校验生成必须基于检索片段。
  - 无片段时拒绝调用模型。

### 行为边界

- 学生问答和教师备课可使用真实模型。
- 输出必须展示引用来源。
- provider 调用失败不能破坏作业提交、内容审核等核心业务流程。
- 不做无来源知识扩写。
- 不把模型输出自动写成正式评分或不可追溯结论。
- 模型输出标注为草稿或建议。

实施前需要查阅 OpenAI 官方文档，确认当前 API、模型名、请求参数和错误处理方式。

## 文字作业 AI 辅助批阅与掌握度

试点版本只覆盖文字作业。语音作业继续保存录音并进入教师人工批阅。

### 批阅流程

1. 学生提交文字作业。
2. 提交状态为 `human_review` 或 `ai_suggested_pending_review`。
3. 教师在批阅页点击生成 AI 建议。
4. 服务端读取作业题目、学生答案、任务目标和已发布知识片段。
5. AI 返回评分建议、评语草稿、薄弱点标签和改进建议。
6. 系统保存 AI 建议，但不写正式分数。
7. 教师确认或修改分数、评语后，提交状态更新为 `reviewed`。
8. 掌握度只基于教师确认结果更新。

### 数据模型

新增 `submission_reviews`：

- `submission_id`
- `reviewer_user_id`
- `final_score`
- `final_comment`
- `ai_suggested_score`
- `ai_comment`
- `weakness_tags_json`
- `status`

新增 `assignment_objectives`：

- `assignment_id`
- `objective_id`
- `weight`

保留 `mastery_snapshots`，但更新逻辑改为由教师确认评分触发。

### 安全边界

- AI 建议必须标注“教师确认前不生效”。
- 模型输出不进入家长报告，除非教师确认。
- 教师只能批阅自己班级的提交。
- 最终评分和 AI 建议生成都写审计日志。
- 未配置模型时隐藏或禁用 AI 建议按钮，人工批阅照常可用。

## 前端工作台改动

第一阶段不重做视觉系统，只补齐试点流程需要的页面、表单和状态。

### 管理员端

- 成员管理：创建成员、设置临时密码、停用或启用账号、重置密码。
- 学生与监护人绑定：支持多学生和多监护人关系维护。
- 内容中心：上传 PDF/DOCX/TXT、查看抽取和切片状态、预览片段、审核发布或拒绝。
- 服务状态：显示 OpenAI provider、模板 fallback、D1/R2 和内容处理能力状态。

### 教师端

- 班级管理：创建班级、分配学生、查看班级成员。
- 任务管理：创建任务、关联学习目标、发布任务。
- 作业批阅：查看文字和语音提交；文字作业可生成 AI 建议；教师确认后写入最终评分。
- 来源化备课：使用新 provider 链路，展示模型或模板状态和引用来源。

### 学生端

- 首次登录改密。
- 查看已发布任务。
- 提交文字作业和录音作业。
- AI 课堂基于已发布内容回答；没有来源时明确拒答。
- 成长档案只展示教师确认后的结果。

### 家长端

- 查看绑定学生列表。
- 切换学生查看学习报告。
- 保留家庭提醒和授权管理。
- 不展示未确认的 AI 批阅建议。

### 前端错误处理

- `401`：标准模式跳登录；首次登录跳改密。
- `403`：提示角色或绑定关系不足。
- `422`：提示内容未准备好、无来源、文件不支持等业务原因。
- `5xx`：提示稍后重试，并保留用户输入。

## 测试与验证

第一阶段验证重点是权限、数据隔离、内容处理、AI 降级和教师确认链路。

### 账号与认证

- 密码哈希验证。
- 临时密码首次登录必须改密。
- 停用账号不能登录。
- 非管理员不能创建成员或重置密码。

### 权限与数据隔离

- 教师只能看自己班级。
- 学生只能看自己的任务和提交。
- 家长只能看绑定学生。
- 多监护人和多学生绑定查询正确。

### 内容管线

- TXT、DOCX、PDF 文本抽取成功路径。
- 扫描 PDF 或不可解析文件进入 `failed`。
- 未发布片段不能被检索。
- 已发布片段可被学生问答和教师备课引用。

### AI 生成

- 未配置模型时走模板 fallback。
- 无来源时拒绝生成。
- provider 调用失败时降级或返回明确错误。
- 引用记录写入 `citations`。

### AI 批阅

- AI 建议不直接更新正式分数。
- 教师确认后才更新提交状态和掌握度。
- 非任课教师不能批阅。

### 构建验证

- `npm run lint`
- `npm test`
- `npm run build`
- 可行时运行 `npm run build:standard`

## 实施顺序建议

1. 账号与成员模型：多用户登录、临时密码、首次改密和成员管理。
2. 权限与聚合数据：按角色和绑定关系修正 workspace 查询。
3. 内容管线：PDF/DOCX/TXT 抽取、切片和审核发布。
4. AI provider：OpenAI provider、模板 fallback 和来源约束。
5. AI 辅助批阅：文字作业建议、教师确认和掌握度更新。
6. 前端试点流程：补齐四端必要页面和状态提示。
7. 测试与文档：覆盖权限、内容、AI 降级、批阅确认和试点使用说明。

## 风险与约束

- 多用户账号会替代当前单管理员标准登录的部分假设，必须保留 ChatGPT Sites 和本地开发模式兼容。
- 密码能力必须使用哈希和安全比较，不能记录明文密码或临时密码。
- 内容解析库如果需要新增依赖，应选择维护活跃、Workers 构建兼容、体积可控的方案；新增依赖前需要明确理由。
- PDF 文本抽取对扫描版教材无效，必须向管理员明确失败原因。
- OpenAI provider 需要在实施前核实官方 API 和当前模型配置。
- 应用内 AI 建议不能替代教师确认，避免误导家长或学生。
- 试点阶段不引入 Vectorize，检索质量依赖切片和关键词策略，后续可独立设计向量检索升级。
